# Bootcamp 执行协议 V2（RLAF 课程，agent 专用）

> 本文件定义 **RLAF 式学习闭环** 的全部规则（2026-09-05 V2 重制，替代 V1 四方向按天计划版）。
> **RLAF（AI 反馈强化学习）= 三层反馈闭环**：① 交互层——每轮只交付 1 点，用户反馈驱动节奏；
> ② 产出层——教程内 alpha 全真跑 `qa run`，平台模拟结果即环境反馈；
> ③ 课程层——目标函数 = 通过研究能力笔试+面试，课程只装官方材料点名且"笔试概念/面试能讲/产出链要用"
> 的知识；深度不足的能力交给日常流程（生成/教学模式/复盘）的真实反馈去补。
> **课程定位**：新手教程的目的是**帮助用户成为顾问**（通过研究能力笔试与面试）；
> 其余学习**融合在日常交互中**，教程不承载深度研究能力培养，够用即止。
> **运行方式**：本目录为公开协议与模板（随仓库分发）。个人执行副本建在本地 gitignored
> `docs/bootcamp/`——把 protocol/rubric/mastery.template 复制过去后初始化 `mastery.json`，
> 摸底卷/错题本/答题记录等个人档案只留在本地。
> 文中 `mastery.json`/`private/`/`mock_exam/` 路径均指本地副本内相对路径；教材 `document/courses/` 为仓库公开路径。
> 核心目标：让使用者能**用自己的话、按官方口径**解释四大方向概念——笔试与面试考察真理解，不是背诵。

## 0. 会话起始

1. 读 `mastery.json` 确认：当前阶段（S0-S5）、各知识点状态、到期复习（next_review ≤ 今天）
2. 若上次会话中断：先报告"上次进行到哪、剩余未完成项"，从断点继续
3. 开场向用户报告：当前阶段 + 本次推进的知识点 + 到期复习项 + 当前最弱 3 考点（来自档案）

## 1. 学习闭环（会话制，无天数排期）

```
**RLAF 交互纪律（最小交互单元，优先级高于分步细则）**：
  每轮只交付 1 个点（1 个概念 或 1 道题）→ 等用户消化/作答/反馈 → 点评或确认通过
  → 才给下 1 个点；知识小块化（单点体量 ≤ 一小段话），少量多次，禁止整节灌输、
  禁止一次性抛多题；每轮之间主动留交互口，节奏由用户逐轮反馈驱动（答错/复述不清
  = 信号 → 换角度回讲该点，不赶进度）。

① 开场诊断（每次会话）
    规则：到期复习必考——昨日错题必重考（出变体：换数字/换场景/换角度，不原题重考）；
        next_review ≤ 今天的考点抽 2-3 个快速口答（RLAF：一次 1 题，逐题点评）；
        诊断结果并入 ③ 的出题池。
② 精学（按知识点推进，不按天）
    规则：从 document/courses/ 取当前阶段教材 → 按"讲为什么"精讲：
        - **主线 = 官方公开课四节 + /learn 教程点名概念**（四方向考纲映射见
          courses/official_quiz-guide.md）
        - **权威分级（教程按官方口径设计）**：主线=四节新手课 + 官方 /learn
          文档点名的概念机制（唯一考题来源）；官方未明示的边角细节（次数/
          具体数值类）与**本地运行经验**（playbook/模板实证/decay 经验值等
          非官方口径知识）同属延展层——口头带过即可，**不设考题、不追问**，
          用户主动问才展开
        - **排序原则：基础先行、主线优先**——先讲"是什么/为什么"，再推机制，
          参数/经验数值放最后；到期复习集中成独立小节放在主线之后，不穿插
          主线中间（跨阶段错题变体重考放开场诊断 ①）
        - 深度上限 = **面试五分钟标准**：笔试概念层 / 面试能讲清 / 产出链要用，
          三处无用即略过；少即是多
        - **术语中英对照**：核心术语首次出现配中英对照（如 decay=衰减、
          neutralization=中性化、turnover=换手率、truncation=截断、delay=延迟），
          不假设用户认得英文术语（用户 2026-09-05 重申要求）
        - 先讲概念为什么存在/解决什么问题；关键机制逐步推导（公式、流程）；
          用课程笔记中的讲师比喻/案例帮助记忆
        - 每讲完 1 个点（概念/机制小块）→ 立即让用户用自己的话复述或提问（费曼单点化）；
          复述不清 = 没懂 → 换角度回讲该点 → 通过才进下一点（禁止讲完整节再问）
        - 拆解教学法（表达式/算子类）：嵌套表达式**先查负号**（方向开关）再**从内到外**
          逐层拆、逐层标注横/纵方向；优先用 qa.db 真实提交记录当例子（用户自己的
          表达式最有感；个人素材只进本地，不进公开文档）
③ 自测（当前阶段知识点考核）
    规则：出题 3-5 道，配比按 rubric；**出题范围 = 当前阶段 core 考点**：
        抽题权重：学习中考点 50% / 到期复习 30% / 新考点 20%；错题变体优先；
        **顽固错点换维度**：同一考点变体连续 2 次未达标 → 换题型维度（A 概念 →
        C 辨析/场景/计算），不重复同型题；
        逐题交互：一次只抛 1 题 → 用户作答 → 点评完毕 → 再出下一题；
        用户答"不会"计 0 分，不追问、直接讲该题要点
④ 评分反馈
    每题按 rubric 打分 → 错因归类（概念混淆/记忆缺失/计算错误/表达不清）
    → 给出标准答案要点（注明官方口径出处）→ 给记忆锚点（比喻/口诀/关联）
    → 阶段小结：知识点状态变更建议。
⑤ 档案更新（每次会话收尾必须完成——中断前也先做这步）
    更新 mastery.json：每题命中→wrong_count/status/confidence/last_review/next_review；
    写 private/错题本（追加今日错题：题目+你的答案+标准要点+错因）；
    写本次推进记录 + 下次推进建议。

**疲劳信号（会话管理）**：连续 2 题明显低于该考点近期水平（串位/粗心型错误、
简单题失分）→ 主动建议收尾改日再学——同日密集重考效果差（间隔 > 密集），
用户坚持继续则记录"用户覆盖"并降低单轮难度。
```

## 2. 状态机、门控与调度（mastery.json）

- status：未学 → 学习中 → 达标 → 熟练
- 升级：单题 ≥8 且连续 2 次 → 达标；≥9 且 3 次 → 熟练；单题 <6 → 保持/回到学习中
- confidence：0-1，按近 3 次得分滑动更新（0.3·本次分/10 + 0.7·旧值）
- next_review：错题=明天；达标后=+2 天；熟练后=+4 天抽查
- **阶段门控**：当前阶段 core 考点全部 ≥ 达标 → 解锁下一阶段；进入新阶段先做段前诊断
  （protocol §3），已掌握考点直接计"达标"（confidence 0.8），跳过重复精学
- **用户覆盖条款**：用户明确要求推进时（破门控/提前到期复习）允许执行——但不虚标未达标
  考点（保持学习中、挂到期复查自动补齐），并在档案备注"用户覆盖"；同日同考点不重复重考
- 摸底/诊断生成基线：≥8 分考点直接"达标"；4-7 分"学习中"；<4 分"未学"

## 3. 定位诊断（替代 V1 四模块摸底）

1. 首次进入 S0：轻量摸底——四大方向各 2-3 题（A 概念为主），共 ~10 题快速定位起点
2. 进入每个新阶段：段前诊断 3-5 题（该段 core 概念 + 辨析）
3. 诊断结果并入 ③ 的出题池；卷与结果存 `private/diagnosis-<日期>.md`，只存本地

## 4. 题型（详见 rubric.md）

A 概念解释（40%）/ B 机制计算（20%）/ C 概念辨析（20%）/ D 场景判断（20%）
——D 场景题侧重**参数/算子/字段的选择判断**（"这个场景选什么、为什么"），对齐课程出口画像。

## 5. 出口评测（教程毕业）

- 全部阶段门控通过后：
- 模拟笔试：90 分钟闭卷 ~20 题（A×8/B×4/C×4/D×4）；当场计时作答；判分 + 诊断报告 + 薄弱清单
- 模拟面试：30 分钟口答情境——开场自我介绍 → 概念追问（按 mastery 弱项，模拟面试官
  "再讲讲/为什么"式追问）→ "讲一个你提交过的 alpha"（用 qa.db 真实记录，含教程产出①-③；
  讲 hypothesis/结构/为什么有效/失败）→ 收尾
- 面试评分：概念准确 / 用自己的话 / 追问抗压 / 真实性
- 通过 = **教程毕业**：恢复正常流程（不再自动插入学习段）；用户主动深问转
  `document/flows/learning.md`；进阶研究能力由日常生成流程持续补齐

## 6. 出题与合规红线（不可违背）

- 题目只从 `document/courses/` 官方主线教材（四节新手课 + /learn 文档）点名的概念机制产生；
  mastery 考点以官方口径为准，本地运行经验类知识不设题；**严禁收集/引用面经、真题、题库**
- 无官方口径的题目须标注"讲师/课程口径"及日期（官方口径冲突时以最新为准并提示）
- 用户答题内容留在本地（个人），不进 document/、不进 git 提交
- 每次学习段结束输出一行进度（当前阶段达标考点数/总数 + 下次聚焦）

**产出三件套（学习记录 = 提交记录）**：全部走 `qa run` 真实模拟，PASS 即按 submission.md 流程
人工确认提交；每个产出伴随 alpha 复盘四问（假设/结构/结果/重做）+ 一句话讲稿
（private/alpha_pitch.md）——面试"讲你自己的 alpha"素材。教程不背"20 个提交"KPI，
攒量由日常 run 流程自然积累。
**复盘选材纪律**：优先挑用户当前能逐层讲清结构的真实记录；表达式含未学算子/字段的
记录标记"回炉"（S3/S4 学毕再拆）——复盘暴露一条"讲不清的提交"比多讲一条更有价值。
