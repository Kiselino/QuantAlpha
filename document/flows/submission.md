# 提交环节（submission）

> 读取时机：**有 PASS 待提交时**（`qa report --pending` 或启动检查发现暂存）。
> 本文件定义提交前的检查、人工确认流程与暂存机制。
> 门槛数值权威来源：`document/reference/rules.md`（提交门槛章节）。

## 1. 合规红线（不可违背）

**禁止无人值守自动提交**——提交必须展示检查结果 + 等待用户显式确认。
每次提交前重申该红线；`--yes` 仅限用户已在对话中显式确认后使用。

## 2. 提交前置检查清单（对应平台全套 check）

提交前 agent 应自检同维度（`qa submit` 展示全部检查 + 免费相关门）：

| 检查 | 标准（D1） | 说明 |
|---|---|---|
| Fitness | ≥ 1.0（D1）/ 1.3（D0） | 综合质量分 |
| Sharpe | > 1.25（D1）/ 2.0（D0） | 单利夏普，2Y 日频 |
| Turnover | 1-70% | 过高换手 → 模拟参数问题 |
| 自相关 | < 0.7 | Sharpe ≥ 1.375 时豁免 |
| 子宇宙 | `0.75·√(sub/alpha)·sharpe` | 子宇宙持仓约束 |
| 相关门 | 免费相关 max < 0.7 | `/correlations/self` 查询 |

ATOM 单数据集 alpha 放宽：只看 2Y Sharpe D1 > 1。

## 3. 免费相关门排序（v1.5）

PASS 候选调免费相关门参与提交排序：**corr 低者优先**（与现有组合相关度越低，
通过相关门概率越高）。`qa report --pending` 展示排序值（标注"提交前需复查"——
pending 期间的 corr 会随时间变化）。

## 4. 提交流程（人工确认）

```
1. 展示待提交清单（qa report --pending）：每个的 local_id / 描述 / 指标 / 相关门排序
2. 用户逐条确认 → qa submit <alpha_id> --yes
3. 提交后回查 ACTIVE（轮询等待，平台状态更新有延迟）
4. 提交成功 → 自动从 pending 暂存删除该条目（防下次启动误报/重复提交）
5. 提交被拒（相关门/ALREADY_SUBMITTED）→ 直接放弃 + 沉淀，不重试（见 generation.md §4）
```

## 5. 相关门被拒处理

- **直接放弃 + 沉淀，不重试**：已提交集不会自己缩小 → 相关值不会自然下降，等待无意义
- 平台判断是最终判断；重试会撞 `ALREADY_SUBMITTED`
- playbook 铁律一致（同簇只留最优版、被拒即弃）
- 生成侧靠"避开已提交信号簇"从源头减少此类被拒（failures 沉淀消息带该提示）

## 6. 提交被拒归因

提交被拒（`sub_*` / `corr_*`）与模拟失败（`f_*`）**分开统计**（修复路径不同：
模拟失败→优化表达式；提交被拒→避开饱和簇）。`qa report` 归因统计分两节展示。

## 7. 提交后经验沉淀

提交结果自动沉淀进 `experience/playbook.md` / `failures.md`（见 `document/flows/experience.md`）。
